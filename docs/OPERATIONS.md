# Operations

This is the operational checklist for the local pilot. Exact commands and tested results must be copied from the finished runtime and [`HANDOVER.md`](HANDOVER.md); unexecuted procedures below are marked as targets.

## Local launch

Target prerequisites are a supported Python runtime, Node/pnpm, Docker Compose and PostgreSQL. The product requirements requires a documented one-command demo after prerequisites/configuration, Windows PowerShell and POSIX quick starts, migration setup, and health checks. The initial host inspection found Node `v24.18.0`, pnpm `11.19.0`, a Docker CLI whose daemon was initially unavailable, and a broken `npm` command. The daemon later became available: local Compose build/start succeeded on 2026-09-28. `uv` may need `UV_CACHE_DIR` inside this writable workspace on this host. The Compose files pin PostgreSQL `17.10-alpine3.22`, Python `3.12.11-slim-bookworm`, Node `22.19.0-bookworm-slim` and nginx `1.29.1-alpine3.22`; these container paths were exercised by the Compose DEMO run.

```text
Windows PowerShell: .\scripts\start-demo.ps1
POSIX shell: sh scripts/start-demo.sh
Direct Compose command (both shells): docker compose up --build -d
Full synthetic data command: python scripts/generate_demo.py --output data/generated
Container init command: python -m quoteflow.cli init-demo --full (called by API container)
Default health endpoint: http://localhost:8080/api/health
Verified host-specific endpoint: http://localhost:8082/api/health with QUOTEFLOW_PORT=8082
```

The PowerShell launcher runs Compose and polls API health for up to two minutes; it succeeded on this host at port 8082 earlier on 2026-09-28. Port 8080 was occupied by another project, so a local ignored `.env` copied from `.env.example` sets `QUOTEFLOW_PORT=8082`. Compose resolves its public/API URLs to that port on this host. Keep the file out of Git and choose a free port on each host. `docker compose config --quiet` and a full Compose build/start passed. PostgreSQL initial seed counts passed and migration reached `a4b1c9d2e3f4`, widening `jobs.status` to `VARCHAR(64)`; `/api/health` returned `ok`, `mode=DEMO`, `synthetic=true`, the web root returned HTTP 200, and synthetic admin login/me returned role `admin`. This is historical evidence: later on the same day Docker reported image/log `input/output error`, the API became unhealthy and `/api/health` returned HTTP 500. The latest source fixes have not been rebuilt into Docker; see [`HANDOVER.md`](HANDOVER.md). The launcher polls API health; the web 200 was checked separately. Compose starts one persistent `python -m quoteflow.cli run-worker` process after API health; `WORKER_POLL_SECONDS` defaults to 10. The code initializes/checkpoints once, uses a fresh DB session per cycle, sleeps while idle and reconnects after an error. Demo mode must display its synthetic/simulated label. Connected mode must require explicit model and HubSpot configuration when those operations are requested; it must not silently return simulator success.

The Compose/PostgreSQL API smoke passed the full proposal-to-acceptance journey with total `$14,875.00`, a 4,805-byte PDF and one unique handoff. The browser test passed through acceptance. After API/launcher restart, PostgreSQL retained 122 briefs, 82 quotes, 188 versions and 32 handoffs; the smoke and browser quotes each retained exactly one handoff. A previously published PDF remained downloadable after API restart (HTTP 200, 4,805 bytes). The first live workflow start exposed `jobs.status VARCHAR(20)` truncation; migration `a4b1c9d2e3f4` widened it to `VARCHAR(64)` and a live retest completed. The retest paused at `waiting_clarification`, resumed after API restart with two answers to three options/`waiting_internal_review`, then moved through admin selection, `waiting_publish_required`, publish, `waiting_customer_review` and portal acceptance to `completed` with one matching handoff. Sixteen checkpoints were recorded for that job.

## Configuration per customer

Create one installation for the customer. Set organization name, brand assets, currency, quote numbering, time zone, catalog and versioned price rules, discount approval threshold, tax/contingency policy, sample terms, retention period, staff roles and connector mode through server-side configuration. Keep secrets outside Git and browser bundles; copy only non-secret examples into `.env.example`. Initialize a fresh workspace and admin account before importing customer data. Check actual catalog pricing and terms with the customer before first quote.

## Connector setup

The local CRM/outbox adapters are the demo defaults. Configure HubSpot contacts/deals only in CONNECTED mode using server-side credentials and documented scopes. Test contact lookup/create, deal upsert and retry/reconciliation against a disposable account or controlled test records before customer use. Show connector health and last error. A missing credential, rate limit, permission error or ambiguous timeout should leave an actionable pending/failed/uncertain state; do not mark delivery successful. Never use real recipients during demo.

## Jobs, retries and recovery

Long jobs need persisted status, progress, cancel request, bounded attempts and failure reason. Workers claim leases atomically and recover expired leases. After Compose rebuild with the persistent worker, startup emitted one Alembic info pair and was quiet while idle. A separate synthetic running job with a manually expired lease was recovered within a poll to `waiting_clarification`, produced one `worker_activity` log and was then cancelled; actual process-crash and concurrent-worker recovery remain unverified. The DEMO worker did not send external mail. Docker stats sampled worker CPU at 0.00% while idle and 0.31%/about 99 MiB after recovery; the previous short-process loop had a transient 99.38% single-core sample. These snapshots are not a sustained benchmark. Outbox actions carry a stable event key and an external idempotency key where supported. Retry only definite failures with bounded backoff. On an uncertain provider timeout, query/reconcile remote state before another write. Keep correlation/run IDs in structured business-event logs without source documents, credentials or portal tokens by default. Record model tokens and known/unknown cost indicators per run; optional LangSmith tracing must remain opt-in and redacted.

Portal review links contain bearer tokens in the URL path. The local container command disables Uvicorn access logs with `--no-access-log`, and Compose nginx uses `access_log off;` to avoid logging `/portal/...` and `/api/portal/...` paths. Nginx also sends `Referrer-Policy: no-referrer` so browsing away from a portal page does not pass the token URL in a referrer header. A `uvicorn.access` filter redacts API portal tokens if access logging is enabled elsewhere; its unit regression test passed in the 31-test backend suite. These controls were added after local DEMO access logs exposed synthetic tokens. Business-event records without token values remain available. A boolean inspection of API/web logs from the earlier healthy Compose run found no `/portal/` path; this spot check does not cover upstream logs, all future requests or tracing. For a customer deployment, separately disable or redact URL logging in any upstream proxy, CDN, WAF, APM and tracing product, and set retention/revocation procedures for previously captured links. Never paste token-bearing URLs into support tickets or shared logs.

## Backup and restore

Back up PostgreSQL application records, graph checkpoints and scoped asset storage at a consistent point; record schema/migration version and catalog version. Encrypt backups and apply a retention period chosen for the customer. A custom-format `pg_dump` was restored into a separate disposable PostgreSQL database on 2026-09-28. Its migration/version and snapshot counts matched live exactly: 2 workspaces, 54 clients, 124 briefs, 83 quotes, 191 versions, 33 handoffs, 21 checkpoints and 3 `proposal_assets` database rows. Separately, the API volume held three synthetic PDFs of 4,805/4,877/4,801 bytes; a tar archive of `/app/assets` was extracted into `/tmp/quoteflow_assets_restored` in the API container and `diff -qr` exited 0, confirming byte-for-byte equality. The disposable dump/database and tar/extraction directory were removed. These are separate database and local asset checks, not a coordinated cross-volume restore into a separate installation; encrypted backup storage and a restored application workflow remain unverified. A complete restore drill must bring both stores up together, open an approved PDF, resume a paused workflow and check for duplicate handoff/outbox writes.

## Retention and deletion

Set customer-specific retention for raw briefs, attachments, rendered PDFs, portal events, logs, traces and backups. Expire review tokens promptly and revoke them on quote replacement. Provide an operator path to redact or delete stored sensitive content and remove it from future trace exports. Deleting a demo workspace must affect only its own namespace. Document any legal preservation requirements with the actual customer before deletion; sample terms are not a legal determination.

## Release and incident checks

Before a customer pilot: run migrations on a copy, domain/integration/access tests, full synthetic data checks, UI/PDF review, backup/restore smoke test, dependency/license review, and a controlled connected smoke test with a spending limit. During an incident, pause connector delivery if outcomes are uncertain, preserve event IDs and logs, inspect action ledger/outbox and provider records, reconcile, then resume. Rotate compromised credentials and revoke tokens/sessions as needed. Record actual outcomes in [`EVALUATION.md`](EVALUATION.md) and [`HANDOVER.md`](HANDOVER.md).
